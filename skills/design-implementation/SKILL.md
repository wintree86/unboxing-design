# Design Implementation

승인된 화면을 구현 기준으로 삼는다. 기능 우선 구현, 기본 UI 라이브러리의 편의, 번역 대응을 이유로 구성·문구·위계·조작을 재설계하지 않는다. 새 디자인 탐색은 design-bot의 범위다. 기능 테스트 통과와 디자인 일치는 별도 결과다.

## 기준 연결

1. 기존 사용자 지시·선택 이벤트에서 구현할 버전을 확인한다. ‘이 디자인으로 구현’은 기존 시안을 구현할 근거다. 이미 승인된 일을 다시 승인받지 않는다. 작업명이 바뀌었다고 전체 구성을 변경하지 않는다.
2. 실제 디자인 도구로 대상 프레임과 상태를 읽고 PNG·노드 측정·필수 자산을 연결한다. `.pen` 내용은 전용 도구로만 접근한다. 파일 시스템에서는 크기·수정 시각만 기록한다. 캡처만 있고 편집 원본에 접근할 수 없다면 그 한계를 기록하며 측정값을 추측하지 않는다.
3. [구현 계약](references/contract.md)에 따라 이번 범위의 화면/상태/기기, 동일 데이터·언어·배율·가용 크기, 주요 요소/행동/토큰과 원본 근거를 고정한다. 제품 요구와 승인된 시각 구성이 충돌하면 해당 차이를 구체화한다. 먼저 독립적으로 가능한 구현을 진행한다.

## 구현

4. 대표 화면 하나를 완성해 비교한 뒤 공통 컴포넌트와 나머지 화면을 확장한다. 사용자가 지정한 순서·범위가 있으면 우선한다. 시안의 실제 자산·폰트·크기·간격·색·표면을 소비한다. Material/Cupertino 등 기본 위젯은 시안에 맞게 조정한 경우 사용한다.
5. 미구현 기능은 기능 상태로 기록한다. 연결·듣기 등을 제거하거나 샘플 버튼 등 다른 동선으로 바꾸는 근거가 되지 않는다. 승인된 비활성/준비 중 상태가 있으면 사용하고, 없으면 원래 화면을 보존한 구현 범위를 분리해 보고한다. 구현 편의를 위한 시안 변경·허구의 동작·샘플 데이터의 실데이터 위장은 금지한다.
6. 반응형은 승인된 기기별 프레임과 규칙에서 구현한다. 임의의 breakpoint 하나로 Mac/태블릿을 휴대폰 화면으로 대체하지 않는다. 규칙이 없는 크기는 기존 위계·행동을 보존하는 임시 적응으로 표시하고 해당 크기도 검증한다. 다국어/접근성 때문에 바뀐 부분은 같은 조건의 전후를 남긴다.

## 실제 비교와 완료

7. [측정과 비교](references/capture.md)를 따라 실제 앱을 기준과 같은 상태·크기·배율·언어·데이터로 실행한다. 원본/실제/오버레이를 관찰하고, 렌더된 요소의 좌표·크기·문구·조작 집합·스타일·자산을 측정한다. 설정값·구현 상수·기능 테스트 로그를 렌더 측정으로 입력하지 않는다.
8. [검사기](scripts/verify.py)를 실행한다. `MATCHED`는 제출한 측정·지문·비교 기록이 일관된다는 뜻이다. 시각적 의미, 사용자 승인 진위, 전체 화면의 자동 인증을 뜻하지 않는다. 실패를 지우거나 허용 오차를 늘려 통과시키지 않는다. 수정한 요소를 소비하는 모든 화면을 재검사한다.
9. 보고는 **기능 결과 / 시안 대비 실측 / 미구현·미검증**으로 나눈다. 대표 화면만 검증했으면 그 범위만 완료로 표시한다. 현재 코드·캡처와 연결된 비교 및 남은 차이 0개가 없으면 ‘디자인 구현 완료’라고 보고하지 않는다. 시각 적합성 검토와 실제 사용자 피드백은 수치 결과와 별도로 남긴다.

구현 담당은 기준·실제 측정·차이 목록을 만든다. 리뷰 담당은 현재 원본과 앱을 직접 비교하고 누락·재구성을 검사한다. 같은 에이전트의 자기 검토는 독립 리뷰로 기록하지 않는다. 추가 에이전트·채팅은 자동 생성하지 않는다.

산출물은 프로젝트 `docs/design-implementation/{run-id}/`에 둔다. 코드와 문서가 분리된 환경은 해당 프로젝트의 기존 경로를 따른다. 새 파일은 이전 실행·승인·실패 근거를 덮어쓰지 않는다. 이 스킬은 새 스토어·배포·원격 쓰기 권한을 부여하지 않는다.
