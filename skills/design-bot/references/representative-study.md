# 대표 화면을 먼저 완성하기

새 디자인 방향을 만들거나 사용자가 기존 시안을 단순함·유사함·완성도 부족으로 거절했을 때 적용한다. 기존 확정 디자인의 작은 수정은 관련 연구와 결정이 유효하면 재사용한다. 화면 수, 장식 수, 레퍼런스 수는 품질 지표가 아니다.

## 1. 비교할 한 장면 고정

제품의 핵심 과업과 목표 인상이 함께 드러나는 screen/state/viewport 하나를 고른다. 대상 사용자의 실제 언어와 데이터, 행동·목적지, 필수 조건, 이전 시안의 버전을 고정한다. 후보별 정보 순서·묶음·밀도는 열어 둔다. 다른 화면에 정보를 옮겼다면 접근 경로를 남긴다. 사용자의 거절 원문을 이번에 바꿀 화면 특징에 연결하고, 이 해석을 사용자 결정으로 쓰지 않는다.

## 2. 이미지를 해부하고 구성 연구로 검증

각 방향의 핵심 레퍼런스를 실제로 열고, 원본을 보존한 채 별도 분석 보드에 영역 번호·화살표·설명을 배치한다. 검색 카드와 무드 키워드만으로 이 단계를 마치지 않는다.

| 분석 대상 | 이미지에 표시할 내용 |
|---|---|
| 시선과 위계 | 진입점, 두 번째 정보, 주 행동, 제목·본문·메타데이터의 대비 |
| 구성과 비례 | 영역 경계, 화면 대비 면적, 여백, 정렬선, 반복 간격 |
| 타이포그래피 | 크기 관계, 줄 수, 행간, 굵기·서체 성격. 실제 폰트명을 모르면 추정 표시 |
| 밀도와 리듬 | 강약이 바뀌는 구간, 열린 여백과 압축된 정보의 역할 |
| 소재와 디테일 | 이미지·표면·선·아이콘·색 강조가 콘텐츠를 돕는 방식 |

이미지에서 잰 비율·거리와 추정치를 구분한다. 추정한 원본 폰트/그리드를 사실로 적지 않는다. 대표적인 영역을 편집 가능한 글자·도형·이미지 레이어로 재구성해 원본 옆에 둔다. 전체 앱을 복제할 필요는 없지만, 핵심 구성 원리를 알아볼 수 있는 범위여야 한다. 재현 이미지와 원본의 영역 비율·위계·정렬 차이를 기록하고 설명하지 못하는 차이를 먼저 고친다. 재현의 목적은 관찰 이해이며 원본과의 유사도를 디자인 우수성으로 쓰지 않는다.

연구본은 `designs/ui/{run-id}/studies/` 또는 원본 안의 명시적인 연구 프레임에 제품 후보와 구분해 저장하고 원출처·관찰 시각을 붙인다. 외부 작품의 연구용 재현을 우리 제품 시안이나 배포 자산으로 표시하지 않는다. 관찰·구성 연구·제품 번역 근거는 `docs/design-harness/{run-id}/study.md`에 연결한다.

## 3. 우리 콘텐츠로 독립적으로 번역

시안·목업 요청은 [완성 목업 기준](finished-mockup.md)을 적용한다. 구조 연구를 바탕으로 필요한 이미지와 표면 견본을 먼저 준비하고, 실제 콘텐츠를 담은 대표 화면에서 디테일까지 마무리한다. 필요한 자산을 임시 도형으로 남긴 채 화면 수나 측정 통과로 완성도를 대신하지 않는다.

각 방향을 쓰기 전에 “사용자가 먼저 무엇을 보고, 무엇을 느끼며, 다음에 무엇을 하는가”를 한 문장으로 적는다. `레퍼런스의 원리 → 제품에서 필요한 이유 → 바꾸는 구성 → 실제 적용 노드`를 연결한다. 참고의 색만 남고 정보 위계·비례·리듬이 사라졌으면 번역을 다시 한다.

기본은 대표 화면 두 안이다. 각각의 위계·공간 배분·서체 관계·행동 표현을 빈 캔버스에서 설계한 뒤 비교한다. 후보 공통의 header/card/button 레이아웃을 먼저 만들거나 이전 흑백 좌표를 그대로 색칠하는 방식으로 시작하지 않는다. 글자·도형 생성 같은 중립적인 도구 함수, 접근성 기준, 이미 확정된 브랜드 컴포넌트는 재사용할 수 있다. 브랜드 제약으로 같은 구조를 유지해야 한다면 차이를 시각 표현 대안으로 설명하고 UX 대안으로 과장하지 않는다.

아래 질문을 실제 렌더를 보며 순서대로 다룬다. 다채롭게 꾸미기 위한 의무 항목으로 쓰지 않는다.

- 첫 시선과 두 번째 시선이 제품 과업에 맞는가? 같은 크기의 상자·제목 반복 때문에 강약이 사라지지 않는가?
- 제목, 본문, 시간·숫자, 보조 정보의 크기·굵기·줄바꿈이 각각 역할을 갖는가?
- 화면의 큰 여백과 촘촘한 구간이 이유를 갖는가? 실제 콘텐츠를 넣어도 균형이 유지되는가?
- 이미지·색·선·표면·아이콘이 제품 맥락에서 기능하는가? 제거했을 때 무엇이 사라지는지 설명할 수 있는가?
- 정렬선, 간격, 모서리, 구분선, 아이콘과 글자의 중심, 선택/완료 상태까지 한 방향의 언어로 마무리됐는가?

## 4. 비교와 수정

동일 화면의 `원본 레퍼런스/분석 → 구성 연구 → 이전 시안 → 새 시안`을 한 보드에서 연결한다. 이전 시안과 새 시안의 뷰포트·배율을 같게 두고 핵심 부위 확대를 덧붙인다. 이전 시안이 없으면 없다고 표시하며 비교용 가짜 기준선을 만들지 않는다.

[하네스의 시각 검토](../../design-harness/references/visual-review.md)에 채택 원리의 적용 노드, 전후 변화, 장단점, 해결하지 못한 점을 넘긴다. 둘 다 약하면 문제의 원리를 고쳐 대표 화면을 재제작한다. 후보 이름 변경·색 교체·화면 추가로 같은 거절을 덮지 않는다. 구조의 독립성과 시각 표현의 독립성을 따로 검토하며, 같은 팔레트·서체·표면으로 수렴했다면 요청에 맞는 차이인지 설명하고 필요하면 다시 제작한다. 자동 수정은 기존 예산 안에서 수행하고 상한에 닿으면 근거와 남은 선택지를 보존한다.

방향 선택 후에만 선택된 화면에서 토큰·컴포넌트 규칙을 추출해 확장한다. 확장본은 대표 화면의 위계·비례·밀도·표현이 유지됐는지 대조한다.
