# 완성 목업의 표현과 비교

사용자가 ‘디자인 시안’, ‘완성 목업’, ‘구현됐을 때의 모습’을 요청하면 읽는다. 구조·와이어프레임을 명시적으로 요청한 경우에는 그 범위를 따른다. 여기서 완성도는 **합의한 대표 화면의 표현 수준**이며 전체 제품 완료나 사용자 최종 승인을 뜻하지 않는다.

## 결과물의 수준을 먼저 맞춘다

구조안은 정보·행동·배치를 설명한다. 시각 방향 연구는 서체·색·소재·표면을 시험한다. 완성 목업은 이 둘을 실제 콘텐츠와 사용할 품질의 자산으로 결합해 제품이 구현됐을 때의 모습을 보여준다. 구조와 색 토큰이 정리됐다는 이유로 마지막 단계를 생략하지 않는다.

현재 요청의 수준을 brief에 기록하고 결과도 그 수준으로 부른다. 이미지가 필요한 위치의 단색 상자, 임시 텍스트 표지, 기본 아이콘과 균일한 카드만 남아 있으면 해당 부분은 연구 중이다. 실물 기기 프레임을 씌우거나 그림자를 추가하는 것으로 앱 내부의 미완성을 보완했다고 보지 않는다. 실제 앱 크기로 볼 수 있는 평면 화면을 함께 제공한다.

## 표현에 필요한 레퍼런스를 찾는다

새 시각 방향의 기본 탐색은 실제 앱의 과업 관찰과 Pinterest·Dribbble의 시각 작품 탐색을 함께 사용한다. 탐색 시작과 인증 준비는 [브라우저 세션 절차](reference-session.md)를 따른다. 사용자 지정 탐색처가 있으면 우선한다. 이미 확정된 브랜드·충분한 작품 레퍼런스를 재사용하는 작은 수정은 그 근거와 생략 범위를 기록할 수 있다.

Pinterest에서는 과업/화면 유형과 목표 인상/소재를 조합해 검색하고, 채택할 핀의 상세 이미지와 연결된 원출처를 연다. 검색 결과 카드만 훑고 탐색 완료로 기록하지 않는다. 핀 게시자, 실제 작가, 출시 앱, 연습 컨셉, AI 생성·수정 표시를 구분한다. 스튜디오 홈만 연결되면 개별 작품의 원작 확인은 미완료다.

Dribbble에서는 검색 결과에서 개별 shot을 열어 실제 이미지·작가·작품 설명을 대조한다. 공개 검색이 되더라도 로그인 여부는 별도로 기록한다. 출시 제품과 컨셉·UI kit·교육 예제를 구분한다.

접근 실패나 도구 한계는 실패 화면/원인과 대체 관찰을 남긴다. 실제로 시도하지 않은 탐색처를 접근 불가로 추정하지 않는다. 지정 탐색처를 확인하지 못했다면 그 요구는 미충족으로 남기되 독립적인 제작 준비는 계속한다. 추가 계정·외부 저장·댓글·게시를 임의로 수행하지 않는다.

## 이미지와 표면을 실제로 제작한다

아트디렉션마다 아래 관계를 짧게 기록하고 실제 노드/프리뷰로 연결한다. 장식 요소를 모두 넣으라는 체크리스트가 아니다.

| 표현 | 결정해야 할 내용 | 산출물에서 볼 근거 |
|---|---|---|
| 콘텐츠 이미지 | 표지·사진·아바타·도표가 담당하는 정보와 크롭 | 사용할 파일, 품질/해상도, 프레임·이미지 노드 |
| 브랜드 소재 | 일러스트·배경·질감이 만드는 인상과 콘텐츠와의 관계 | 관찰 원리, 생성/구매/제공 출처, 실제 적용 |
| 빛·색·표면 | 그라데이션·광원·투명도·그림자의 역할 또는 단색을 유지할 이유 | 효과가 보이는 렌더 영역, 가독성과 깊이 |
| 서체·디테일 | 제목/본문/숫자 관계, 아이콘, 구분선, 진행·선택 상태 | 실제 내용이 들어간 확대 부위와 화면 전체 |

필요한 자산은 제공 자료·사용 가능한 라이선스 자료·연결된 이미지 생성 도구로 확보한다. 프롬프트·출력·채택/폐기 이유, 원본과 최종 크롭/효과를 연결한다. 이미지 생성 도구가 있더라도 완성 UI 전체를 한 장의 비트맵으로 대체하지 않는다. 글자·조작·레이아웃은 편집 가능하게 유지한다.

같은 책의 실제 표지처럼 콘텐츠 정체성인 자산은 비교안 사이에서 유지한다. 대체 표지 자체를 탐색한다면 그 범위를 명시한다. 연구용 외부 작품 이미지를 제품용 자산으로 넣지 않는다. 자산이 아직 없으면 임시임을 표시하고 그 상태를 완성 목업으로 제시하지 않는다.

그라데이션·이미지·질감을 쓰지 않는 방향도 가능하다. 제품 과업·확정 브랜드·관찰한 레퍼런스에 맞는 의도적 선택이어야 한다. 도구 호출을 줄이거나 정적 측정기를 통과하기 위한 단색 축소는 이유가 되지 않는다. 이미지 위 대비 등 도구가 못 재는 부분은 별도 근거 또는 미측정으로 남기며, 임의 값으로 gate를 통과시키지 않는다.

## 구조 차이와 시각 차이를 따로 검토한다

후보마다 구조 가설과 시각 방향을 분리해 쓴다. 독립적인 시각 방향이 요청됐다면 색상뿐 아니라 서체 관계·이미지 연출·빛/표면·여백/밀도·조작 디테일이 실제로 어떤 다른 인상을 만드는지 나란히 대조한다. 모두 억지로 다르게 만들 필요는 없지만, 두 결과가 같은 스타일로 수렴했다면 그 이유와 변경을 기록한다. 구조만 다른 안은 그렇게 설명한다.

레퍼런스의 완성 화면/핵심 확대, 편집 연구, 이전 안, 새 안을 연결하고 다음을 검토한다.

- 레퍼런스에서 인상을 만든 주요 소재와 디테일이 제품 번역에서 사라지지 않았는가?
- 실제 콘텐츠·이미지를 넣은 상태에서 위계·가독성·크롭·버튼·상태가 한 방향으로 마무리됐는가?
- 미완성 자산/표면/조작 상태가 남았는데 수치 검사나 스타일 이름으로 덮고 있지 않은가?

결과는 visual-review.md의 ‘요청 수준 / 표현 반영 / 남은 미완성 / 시각 차이’에 쓴다. 요청 수준에 못 미치면 대표 화면을 수정한다. 별도의 사용자 승인 단계를 추가하지 않고 기존 방향 선택에서 비교한다. 수치 검사 성공만으로 이 검토가 자동 완료됐다고 보고하지 않는다.
