# 레퍼런스에서 화면까지

## 입력

PRD, design-discovery/manifest.json, 기존 선택과 거절, 기술 제약을 읽는다. wireframes/manifest.json과 현재 원본은 존재하면 읽으며 시작의 필수 입력으로 요구하지 않는다. 새 구성은 [선행 탐색 계약](discovery.md)에 따라 와이어프레임 전에 조사하고, 구조 탐색 후 표현을 구체화할 때 레퍼런스를 다시 검토한다. 사용자 원문/해석/가정/제외를 분리한다. 감정과 강도, 장면과 공간, 표현 요소, 유지할 과업, 피할 표현을 brief에 기록한다. 기존 답을 반복 질문하지 않는다.

요구사항을 불변 조건(정보·결과·정책·명시적 사용자 결정)과 탐색 가능한 가정(좌표·시각 순서·묶음·컴포넌트·입력 순서)으로 나눈다. 기존 와이어프레임은 후자의 유일한 정답이 아니다. PRD의 사진 우선·최근순 같은 조건이 실제 첫 화면에 드러나는지 먼저 점검한다. 사용자 확정 배치를 바꾸는 제안에는 원문과 영향을 함께 적고 채택 전 확정으로 취급하지 않는다.

## 탐색과 재구성

한국어·영어로 과업과 감정/소재/공간을 나눠 검색한다. 새 시각 방향은 실제 앱과 Pinterest의 검색·핀 상세를 함께 관찰하고 연결된 공개 원작자 작품을 추적한다. 확정 레퍼런스의 작은 수정은 재사용 근거를 남긴다. [완성 목업 기준](finished-mockup.md)에 따라 UI·사진·일러스트·표면이 실제 제품에서 맡을 역할을 정한다. 접근 실패는 기록하고 공개 대체 경로를 사용한다. 제목·검색 요약만 있으면 관찰 목록에서 제외한다. 외부 계정에 핀을 저장할 필요는 없다.

사용자가 Pinterest 등 특정 탐색처를 명시하면 그 출처의 실제 검색과 핀 상세 관찰을 포함한다. 접근이 막혔을 때 다른 출처만 보고 요구를 충족했다고 기록하지 않는다. 로그인 완료가 알려지면 같은 경로를 다시 확인한다. 핀 게시자·원작자·출시 앱·연습 컨셉을 구분하고 원문 작품 페이지를 따라간다. 링크가 스튜디오 홈으로만 연결되면 작품의 독립 확인으로 세지 않는다. 기존 시안 제작 후 추가한 자료는 사후 보완이라고 밝히고 유지/수정/배제와 전후 버전을 남긴다. 색상 검색만으로 결과가 좁아지면 과업·화면 유형 중심 검색을 함께 수행한다.

관찰 카드에는 URL, 작가/미상, 열람 시각, 관찰 이미지, 구성·서체·색과 빛·질감, 채택/배제, UI 적용 원리를 쓴다. 서로 다른 레퍼런스가 같은 화면 모양으로 수렴하면 왜 그런지 비평한다. 관찰 수나 유사도는 창의성 점수가 아니다.

탐색 과정 검토 요청에는 실제 검색어→후보→접근/캡처 실패→유효 관찰→채택/배제→적용 화면의 경로를 문서로 남긴다. 로드 중·빈 캡처와 검색만 한 후보는 유효 관찰 수에서 제외한다. 스토어 홍보·데스크톱·모바일·구버전 예시를 구분하고, 원 앱에서 관찰한 서체 성격과 새로 선택한 한국어 폰트/색상 토큰을 분리한다.

앱에서는 같은 과업의 상세·탐색·작성 화면을 우선 관찰한다. UI에서 보이는 주체, 핵심 정보, 탐색 단위, 행동 위치, 입력 순서를 기록하고 관찰 사실과 추론을 구분한다. 정적 스토어 이미지만 봤으면 실제 전환·키보드·제스처까지 시험했다고 쓰지 않는다. 무드 자료는 이 UX 근거를 보완한다.

새 시각 방향과 품질 거절 후 재작업은 [대표 화면 제작](representative-study.md)의 관찰 이미지 분석 → 편집 가능한 구성 연구 → 우리 콘텐츠의 대표 화면 순서로 진행한다. 방향별 장면 한 문장, 핵심 표현, 견본, 원출처에서 바꾼 점, 실제 콘텐츠를 담은 UI, 장단점을 만든다. 필요하면 연결된 이미지 생성/편집 도구로 새 소재를 만들고 편집 가능한 글자/버튼과 조합한다. 도구가 이미지 입력을 받지 않았다면 텍스트 해석을 전달한 생성이라고 명시한다. 연구용 재현과 제품 자산을 구분한다. 생성 프롬프트·출력·채택/폐기 이유를 남긴다.

시각 방향을 구체화할 때 `layout_choices`의 임시 배치를 전면 재구성할 수 있다. 사진 비중·제목 위계·그룹·읽기 리듬·밀도를 함께 검토하고, 참고가 색에만 반영됐다면 구성 가설과 실제 화면 사이의 누락을 설명하고 수정한다. 명시적 사용자 결정은 해당 결정의 범위만 고정한다.

## 공정한 비교와 피드백

동일한 screen/state/viewport, 콘텐츠 ID, 행동 결과를 비교한다. 화면에서 한꺼번에 보이는 양과 순서는 설계 변수이며, 스크롤·탭·중간 단계로 옮긴 콘텐츠는 접근 경로를 명시한다. 정보 위계·전환 변경에는 wireframe 계약의 영향과 이유를 기록한다. 기본 첫 제작 범위는 대표 화면 1개 × 독립적인 2방향이다. 방향 수는 비교할 가설과 사용자 요청에 맞추며 더 많은 화면을 기본값으로 만들지 않는다. [시각 검토](../../design-harness/references/visual-review.md)와 기존 방향 선택 뒤 선택된 안만 전체 상태로 확장한다. 두 안 모두 설득력이 약하면 대표 화면을 재작업한다.

구조 탐색 또는 ‘배치가 같다’는 거절에서는 먼저 색·장식과 분리한 구조안을 비교한다. 각 후보가 첫 화면에서 답하는 질문, 사진/본문/메타데이터의 우선순위, 탐색 단위, 작성 순서와 손실을 표로 쓴다. 실제 렌더에서 핵심 사진 면적과 노출 수·행동 위치·정보 접근 단계를 측정하되 숫자를 창의성 점수로 쓰지 않는다. 색과 모서리만 다른 후보는 별개의 UX 대안으로 세지 않는다. 구조 가설이 미선택이면 `exploring`으로 유지하고 완성 UI 비교 gate에 통과한 것처럼 보고하지 않는다.

사용자의 원문을 버전·후보·화면에 연결한다. 예: ‘더 몽환적으로’ → 어떤 빛/질감/공간이 약한지 가설 → 유지할 표현 → 최소 수정 → 전후 프리뷰 → 재측정. 사용자 거절과 에이전트의 추정은 구분한다. 미반영 요청에는 이유를 남긴다.

## 저장과 인계

Pencil의 현재 스킬/API 문서를 읽고 Generate 등의 지원 범위를 확인한다. 저장 후 닫고 다시 열어 MCP의 실제 bounds/content/problem을 읽는다. 원본과 같은 버전의 PNG를 내보내고 readback에 원본/PNG 지문을 결합한다. 원본 메타데이터는 암호학적 내용 증명이 아니다.

대표 비교 전에도 완성 목업에 필요한 이미지·그라데이션·표면·조작 디테일을 실제로 제작한다. 구조 연구용 임시 자산과 완성 시안의 자산을 구분하며, 사용자의 품질 거절을 색상 변경만으로 처리하지 않는다.

선택 뒤 토큰·컴포넌트 상태·서체/자산 규칙·길이 제한을 작성하고 나머지 상태를 확장한다. 확장 후 선택한 핵심 표현을 대표 화면과 비교한다. 독립 검토와 최종 결정이 같은 버전에 연결되기 전에는 builder에 최종본으로 넘기지 않는다. 실제 폰트/기기 동작/스크린리더/글자 확대는 별도 측정 없으면 미확인으로 남긴다.
