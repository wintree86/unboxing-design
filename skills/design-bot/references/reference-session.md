# 레퍼런스 계정과 브라우저 세션

레퍼런스 탐색을 시작하거나 사용자가 Pinterest·Dribbble 인증 준비/연결 확인을 요청하면 사용한다. 이 절차는 호스트가 제공하는 브라우저·계정 연결 기능을 이용한다. Python 실행기나 스킬 설치기가 로그인을 수행하거나 세션을 보관하는 기능은 아니다.

## 먼저 실제 접근 상태를 확인한다

1. 연결된 전용 서비스 도구가 필요한 검색·작품 열람을 지원하면 먼저 사용한다. 부족하면 호스트 브라우저 도구를 쓴다. 사용자 지정 브라우저를 우선하고, 없으면 이전에 사용한 브라우저/프로필의 세션을 재사용한다. 다른 브라우저의 로그인 상태를 현재 도구에 그대로 적용하지 않는다.
2. Pinterest와 Dribbble을 실제로 열어 로그인 상태와 검색·상세 열람 가능 여부를 각각 확인한다. 홈페이지의 계정 메뉴는 인증 단서일 뿐, 검색/작품 접근 성공의 근거는 아니다. 검색 결과 링크와 실제 상세 이미지를 확인한다. 로딩 중인 빈 화면·이전 페이지 잔상은 성공으로 세지 않는다.
3. 기존 인증이 유효하면 재로그인을 요구하지 않는다. **비로그인 상태이면 공개 검색·상세가 가능해도 사용자에게 로그인을 요청한다.** 공식 로그인 화면을 보여 주고 완료 응답을 기다린 뒤 같은 브라우저에서 재확인한다. 사용자가 로그인 없이 진행하겠다고 명시하면 공개 접근으로 이어가고 그 선택을 기록한다. 별도의 인증 준비 요청이 있어야만 이 절차를 시작하는 것은 아니다.

계정 상태는 `authenticated`, `signed_out`, `unknown`, 접근 결과는 검색/상세별 `available`, `login_required`, `challenge`, `failed`, `not_checked`로 구분한다. 공개 열람이 가능하더라도 signed_out이면 로그인 요청을 생략하지 않는다. 로그인 응답 대기는 authentication_pending으로 별도 기록하고 공개 접근 가능 상태를 지우지 않는다. unknown이면 현재 화면의 계정 메뉴/로그인 버튼을 추가 확인하며, 불확실함을 로그인 완료로 바꾸지 않는다.

## 비로그인이면 공식 로그인 화면으로 연결한다

- 사용할 사이트의 공식 로그인 화면을 현재 선택한 브라우저에서 연다. 사용자/호스트가 이미 승인한 정상 로그인 범위는 반복 확인하지 않는다.
- 계정 선택이나 자격 증명 입력이 필요하면 해당 화면을 사용자에게 보여 주고 로그인 완료를 기다린다. 비밀번호·OTP를 채팅/프로젝트 파일로 수집하지 않는다. 계정 신규 생성·약관·CAPTCHA·추가 권한은 현재 호스트의 승인/인계 정책을 따른다.
- 대기하는 동안 다른 서비스의 이미 인증된 레퍼런스 관찰이나 선택된 디자인 제작 등 독립적인 작업은 계속한다. 해당 서비스의 본 탐색은 응답을 기다린다. 로그인하지 못한 부분은 미완료로 남기고, 무응답을 공개 탐색 동의로 간주하지 않는다. 성공할 때까지 같은 인증 요청을 반복 제출하지 않는다.
- 완료 통보 후 같은 브라우저/프로필에서 로그인 표시를 확인하고, 예정했던 검색 1건과 작품 상세 1건을 다시 열어 결과를 확인한다. 사용자 완료 통보만으로 인증 성공을 기록하지 않는다.

인증 준비가 핀 저장, 좋아요, 팔로우, 보드 생성, 댓글, 업로드 권한을 포함하지 않는다. 레퍼런스 관찰에 이런 쓰기 동작이 필요하지 않다.

## 다음 실행에서 재사용한다

세션은 브라우저/연결 서비스가 관리한다. 쿠키·토큰·브라우저 저장소를 추출하거나 다른 프로필로 복사해 유지하지 않는다. 기본 브라우저나 회사/개인 프로필을 임의로 전환하지 않는다.

다음 실행에서는 이전에 사용한 브라우저 힌트를 참고하되 **현재 화면에서 다시 상태를 확인**한다. 세션 만료, 브라우저 초기화, 도구 미연결을 인증 실패와 구분한다. 로그인된 로컬 브라우저가 있어도 에이전트가 그 프로필에 연결되지 않았으면 도구 연결은 미완료다. 호스트가 세션 지속을 보장하지 않으면 재시작 후 유지된다고 약속하지 않는다.

## 근거를 간단하게 남긴다

프로젝트 `docs/design-discovery/access.md` 또는 현재 실행의 조사 기록에 아래만 기록한다. 공유 스킬·배포물에는 실제 계정이나 프로젝트 인증 기록을 넣지 않는다.

| 항목 | 기록할 근거 |
|---|---|
| 확인 시각·서비스 | 실제 확인 날짜와 Pinterest/Dribbble |
| 브라우저 힌트 | 재사용할 도구/브라우저 종류. 이메일·계정명·로컬 프로필 경로는 불필요 |
| 인증 상태 | 관찰한 계정 메뉴/로그인 버튼 등 비밀 없는 단서 |
| 검색 | 실제 검색어·결과 URL·성공/실패. 링크 수는 현재 로드된 수이며 유효 관찰 수가 아님 |
| 상세 | 실제 작품 URL·이미지 열람 여부·로그인 장벽 |
| 남은 작업 | 재로그인/사용자 인계/도구 연결/미확인 항목 |

비밀번호, OTP, 쿠키, 토큰, 인증 응답 원문, 비공개 보드 내용은 기록하지 않는다. 인증 확인과 디자인 조사 품질을 분리한다. 작품의 저자·게시자·컨셉/출시 여부·채택 이유는 기존 [탐색 절차](procedures.md)와 [완성 목업 기준](finished-mockup.md)을 따른다.
