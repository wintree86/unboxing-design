# Design Harness

[환경과 입력 연결](references/environment.md), [실행 계약](references/contract.md)과 [명령 안내](references/commands.md)를 읽는다. 제작은 design-bot 절차, 기술 제약은 대상 프로젝트의 아키텍처·기존 구현을 참고한다. 에이전트 실행을 대신 가정하지 말고 실제 연결된 도구를 사용한다.

1. 기획 이후 [선행 탐색 계약](../design-bot/references/discovery.md)을 수행하고 필수 조건·임시 배치·구성 가설을 와이어프레임에 연결한다. 새 하네스 실행은 discovery와 실제 구조 산출물을 inputs의 지문 대상으로 함께 등록한다. 와이어프레임이 없을 때는 environment.md의 구조 요약을 현재 에이전트가 작성한다. 입력 원본과 사용자 표현을 기록하고 실행 ID를 만든다. `init`은 빈 초안이며 완료가 아니다.
2. `status`의 작업 모드·피드백·선택 유효성을 읽는다. [피드백 적용](../design-bot/references/feedback-application.md)에 따라 새 방향은 대표 화면의 두 안, 기존 방향 수정은 한 안의 전후, 원인 조사는 분석·문서로 분기한다(사용자 지정 범위 우선). [완성 목업 기준](../design-bot/references/finished-mockup.md)으로 요청 수준과 실제 표현을 대조한다. 구조안·표현 연구·완성 시안을 구분하고, 임시 자산·미완성 표면이 남으면 대표 화면을 보완한다. 실제 레퍼런스 분석·편집 가능한 구성 연구·아트디렉션·이전/새 화면·재열기 관찰을 연결한다. [시각 검토](references/visual-review.md)를 읽고 그 근거를 갖춘 뒤 비교를 제시한다. 같은 과업을 비교하되 배치를 고정하지 않는다.
3. 위계·밀도·타이포그래피·디테일·레퍼런스 번역을 실제 화면/노드로 비평한다. 부족하면 대표 화면을 수정한다. `refresh` 뒤 현재 화면에 묶인 `comparison-review.json`을 작성하고 `prepare --stage comparison`을 실행한다. 기술 측정, 검토 현재성, 피드백 처리, 제시본 연결을 각각 검사하며 의미·미적 판단 자체는 자동화하지 않는다. 미처리 피드백은 선택/확장/인계를 막는다.
4. 레퍼런스·구성 연구·이전 시안·새 시안을 함께 보여주고 실제 사용자 방향 선택을 저장한다. 양쪽 모두 부족하거나 사용자가 재작업을 요청하면 선택을 압박하지 말고 같은 대표 범위를 고친다. 새 승인 단계를 만들지 않고 기존 방향 선택에서 처리한다.
5. 선택한 방향의 원리를 토큰·컴포넌트로 정리한 뒤 나머지 화면을 확장한다. 전후 diff와 사용자 원문을 남긴다. 입력이나 선택 방향을 바꾸면 선택이 무효가 될 수 있다. 거절 원본과 실패 근거를 보존하고 기존 상태 이름만 보고 작업을 이어가지 않는다.
6. 독립 리뷰와 전체 범위 측정 뒤 `prepare --stage final`, 최종 사용자 이벤트, `gate` 순으로 인계한다.

자동 수정 상한은 기본 2회이며 상한 초과는 성공이 아니다. 동일 ID 이벤트는 한 번만 처리한다. 무응답·자동 검사·생성자 추천을 사용자 결정으로 기록하지 않는다. 실제 위임이 있으면 run/kind 범위를 확인한다. `.pen` 내용은 일반 파일 읽기로 접근하지 않는다.

이 패키지는 세 스킬과 로컬 실행기를 제공한다. 별도 에이전트를 자동 실행하지 않는다. 상태를 재개할 때 status와 원문 근거를 먼저 읽는다. 연결 도구가 없으면 관찰·생성을 수행했다고 기록하지 않는다.

구현 인계 뒤 실제 코드/화면의 일치는 [design-implementation](../design-implementation/SKILL.md)의 별도 계약과 렌더 비교로 검증한다. 디자인 원본의 측정 성공을 앱 구현 성공으로 보고하지 않는다.
