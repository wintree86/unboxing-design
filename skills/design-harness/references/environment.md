# 환경과 입력 연결

세 스킬은 같은 skills 디렉토리의 형제로 함께 설치한다. 폴더 사이 상대 참조와 design-harness에 포함된 scripts 전체를 보존한다. 특정 회사의 허브·프로젝트 등록부·모델 SDK는 필요 없다.

## 프로젝트와 자료

실행할 프로젝트를 정하고 `scripts/design.py --project-root /absolute/project doctor`로 경로를 확인한다. 기본은 프로젝트 자체가 docs_root/code_root다. `design-kit.json`이 있으면 다음처럼 부모 경로를 바꿀 수 있다. 상대 경로는 모두 선택한 프로젝트 기준이다.

```json
{"schema_version": 1, "docs_root": ".", "code_root": "."}
```

- 기획서·브랜드 규칙·기술 제약·사용자 결정은 회사 프로젝트의 자료를 읽는다. 공유 스킬 본문에 회사 자료를 넣지 않는다.
- 입력 문서가 `docs/` 밖에 있으면 출처와 시각을 적은 스냅샷을 `docs/design-inputs/`에 만들고 지문을 연결한다. 원본이 바뀌면 스냅샷도 갱신하고 비교·결정을 재검토한다.
- 결과는 `docs/design-discovery/`, `docs/design-harness/{run-id}/`, `designs/`에 기록한다. 설치한 스킬 폴더에 제품 결과물을 저장하지 않는다.
- 기존 와이어프레임이 없으면 현재 에이전트가 `docs/design-discovery/structure.md`를 만든다. 요구사항 ID·원문·수용 기준, 화면/상태/뷰포트, 콘텐츠 ID·문구, 행동 ID·목적지, 정보 접근 경로, provisional/user_confirmed 배치와 실제 결정 출처를 적는다. 구조 요약과 discovery manifest를 하네스 manifest의 inputs 배열에 `{path,sha256}`로 연결한다. 요약을 편집 가능한 와이어프레임이라고 보고하지 않는다.
- 이미 와이어프레임이 있으면 실제 산출물을 사용한다. 별도 기획/와이어프레임 봇 설치나 새 채팅 생성을 선행 조건으로 만들지 않는다.

## 연결 도구

호스트 에이전트가 제공하는 도구를 확인한다. 레퍼런스 도구의 최초 사용·인증 준비·세션 만료는 [브라우저 세션과 인증](../../design-bot/references/reference-session.md)을 따른다. 이 패키지는 MCP를 자동 설치하거나 자격 증명을 가져오지 않는다. 브라우저 인증과 CLI doctor의 로컬 파일 검사를 구분한다.

| 작업 | 필요한 기능 |
|---|---|
| 레퍼런스 탐색 | 웹 검색과 실제 이미지/페이지 열람 |
| 편집 가능한 제작 | 디자인 편집기, 원본 저장·재열기, PNG 내보내기 |
| 실측 | 렌더된 노드 ID·부모·bounds·content·fill·problem 관찰 |
| 최종 서체 검증 | 실제 폰트/글리프 관찰 또는 지원되는 별도 렌더러 |

첫 사용 경로는 Pencil이다. 사용 중인 Pencil의 현재 도구 설명을 읽고 실제 연결을 확인한다. `.pen` 내용은 전용 도구로만 읽고 쓴다. 실행기는 `.pen`의 크기/수정시각만 기록한다. SVG 등 다른 편집 가능한 원본도 실제 렌더 관찰을 같은 계약으로 제공하면 사용할 수 있지만, 이 배포가 모든 편집기 연결을 구현했다는 뜻은 아니다. Figma 자동 연결은 포함하지 않는다.

필요 기능이 없으면 가능한 탐색·문서는 진행하고 생성/실측/최종 검증 중 무엇이 막혔는지 기록한다. 스크린샷 인상이나 설정값으로 실제 관찰을 대체하지 않는다. 실제 독립 검토자가 없으면 최종 독립 리뷰는 미완료로 둔다. 새 에이전트·외부 게시·권한 변경의 허가를 이 스킬에서 추정하지 않는다.
